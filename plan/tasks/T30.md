## Interface contract (frozen)

CONTRACTS §4 is exact: `DecisionModel.identity() -> ModelIdentity`, `decide(request: DecisionRequest, *, timeout_s: float) -> CapturedOutcome`, `close() -> None`; `FixtureModel(responses: Path)`, `LayaModel(*, offline: bool = False)`; `normalize(capture: CapturedOutcome, question: ChoiceQuestion, expected_identity: ModelIdentity) -> Outcome`; `fault_capture(lock: PlanLock, spec: FaultSpec) -> tuple[DecisionRequest, CapturedOutcome]`; `run_fault_campaign(lock: PlanLock) -> tuple[FaultResult, ...]`.

Implement the protocol in adapters/base.py without dependencies. Keep normalization.py free of provider imports. Fixture identity is derived from raw fixture bytes, never trusted from a supplied row. Captures preserve exact request hash, actual identity, body/failure exclusivity, bounded warnings and fallback state. Normalization validates identity first, exact labels/types/probability inventory, sum tolerance and returned selected label; native confidence/action metadata never authorizes ACT.

Preserve the full native Laya response object in body_json, including model,
answers and usage. Pure normalization validates exactly the requested answer ID,
the generic native marker and the verified usage/truncation/options diagnostics
before extracting the answer. Missing, extra or malformed fields cannot disappear
in adapter preprocessing. Fixture bodies remain inner-answer objects. Canonical
Laya faults use the exact synthetic zero-usage envelope in CONTRACTS. Test wrong,
missing and extra answer IDs, malformed usage, truncation and collapsed options
through pure normalization and both provider-specific fault campaigns.

Faults consume the six specifications already frozen inside PlanLock, then call the same pure normalizer and T10 evaluator. Implement the exact pure `fault_capture` generator in CONTRACTS §4: scenario ID as request ID, literal state, locked question, canonical request/body hashes, empty warnings/no fallback, first-allowed-label selection and exact per-scenario mutations. Low-confidence injection keeps the **first allowed label** selected at zero probability and gives the first different known label probability one; do not replace it with argmax. Assessment/replay independently compare against these canonical captures, so do not add transient metadata or random order. Do not alter/recreate lock contents or import assessment/replay from faults.py.

## Acceptance criteria (testable)

1. Fixtures reject duplicate/missing requested cases and bad row schema, derive immutable identity, and produce deterministic captures. Pure normalization runs without Laya/Torch/Transformers installed; it rejects all unsupported schema/numeric/label/identity violations rather than coercing them.
2. Preserve provider choice, apply fixture 1e-12 and pinned-Laya `0.00005 * option_count + 1e-12` sum tolerances exactly, normalize the selected probability and surface normalization/native calibration warnings. Reject bool/nonfinite/negative probability and invented keys. Fallback never becomes hidden.
3. The resident spawned native worker uses verified checkpoint/artifact hashes, explicit CPU FP32/four threads/eager/compile=False/fast=False, and the exact upstream preflight in providers.md. Reject state/instruction/option clipping **before inference**, including Unicode/token-heavy edge cases; do not substitute another model/device or silently download in offline mode.
4. Startup is bounded at 120s; the evidence runner always uses 30.0s per request (ADR 0008). The low-level method validates finite positive timeout arguments for direct use/tests. Timeout terminates/kills as needed and joins the owned worker before returning timeout. Later calls are unavailable, not restarted silently; no late result crosses requests. Idempotent close leaves no child alive, including setup failure and exception paths.
5. All six ordered fault results use exact canonical captures and are emitted/re-evaluated: timeout/rate-limit/malformed/identity mismatch → ESCALATE, unknown choice → DENY, selected-low-confidence → ABSTAIN. Fault evidence is separate from regular sample records. `fault_capture` is deterministic, pure and callable without optional-provider imports. A real marked cached-offline Laya smoke must run and report actual identity/warnings, not silently skip into a claimed pass.
