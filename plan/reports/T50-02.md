- `src/actseal/cli.py` (modified; +80/-7 lines)
  1. **Finding 1 (argv values in usage errors).** Argparse diagnostics no
     longer reach the user verbatim. `_Parser.error` passes every message
     through new `_bounded_usage_message`, which recognizes the argparse
     shapes and rewrites them using only parser-defined names: "the
     following arguments are required: <option strings/metavars>";
     "argument <name>: invalid choice (choose from <inventory>)" where the
     inventory comes from the module constant `_CHOICES` (`COMMAND` ->
     lock, verify, replay, demo; `--provider` -> fixture, laya), never from
     the message; "argument <name>: expected one argument" (count shapes
     matched by regex, no value); "argument <name>: does not take a value"
     for `--flag=value` misuse; any other per-argument shape collapses to
     "argument <name>: invalid value"; any unrecognized message collapses to
     "invalid command line; see --help". The `<name>` is the action's option
     string or metavar, which argparse takes from the parser definition, not
     from argv. Leftover tokens are handled by new `_parse`, which uses
     `parse_known_args` and reports only their count: "unrecognized
     arguments: N token(s) not accepted; see --help". Exit code stays 3 in
     text and JSON mode. Module docstring updated.
  2. **Finding 2 (failures summary).** `_failures` now counts each record's
     normalized outcome once: the `ProviderFailure.code` of every record
     whose outcome is a failure. Transport failures pass through
     normalization unchanged, and bodies rejected by normalization
     (malformed response, unknown choice, identity mismatch, input too long)
     become failures only there, so the single outcome count covers both.
     `_warnings` is unchanged from the earlier in-task fix (outcome warnings
     only, which already include the capture warnings once).
  3. **Finding 3 (fixture --offline).** `_check_provider_options` no longer
     rejects `--offline` with `--provider fixture`; the docstring states that

Deviations from spec (with reason)

- Usage diagnostics are rewritten rather than passed through. Bounded
  diagnostics retain option strings, metavars, the accepted choice
  inventory and the count of rejected tokens; the raw token text is dropped
  even for ordinary typos, because the CLI cannot tell a typo from a secret.
  An unrecognized argparse message shape collapses to a generic hint rather
  than risking an echo.
- The `_CHOICES` inventory is a module constant mirrored from the parser
  definition (the subcommand metavar `COMMAND` and `--provider`), because the
  argparse message is the only carrier of the inventory and must not be
  parsed for it. A unit test pins both inventories.
- `--offline` with the fixture provider is accepted and has no effect, as
  required; the earlier rejection and its tests are gone.
- Failure summaries count normalized outcomes, so a captured transport
  failure and a normalization rejection are reported through one field with
  one entry per case; the raw `capture.failure_code` is still in the bundle.
- `lock` still pre-parses both splits before building a provider (recorded
  in REPORT T50); unchanged here.
