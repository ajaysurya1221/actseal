## Deviations

1. **No rendered verification in this session.** The task's "desktop/mobile rendering" test and the supplement's screenshot/label-measurement acceptance require rasterization. `qlmanage -t` (the only rasterizer present locally) was denied by the permission controls; I did not retry it or substitute another mechanism, and no tool download was attempted (resvg is still unfetched). Readability is therefore established only structurally: label sizes ≥ 26/30 units, no transforms, and the conservative width model. Codex must review the actual rendering (1366×900 README first screen, 360 mobile) as the supplement specifies.
2. **Font stack names three concrete faces before the generic family** (`Helvetica, Arial, Liberation Sans, sans-serif`) rather than only generic families. Reason: the five-column desktop layout leaves 260 units per column at 26-unit text, and Helvetica/Arial/Liberation Sans are metric-compatible, so widths are predictable on macOS, Windows and Linux. The widest DejaVu-class fallback would exceed the measured width of `offline; no model call` by about 5 units, which stays inside the 14-unit padding and does not clip. The validator's rule (stack ends with a generic family) is unchanged and not weakened.
3. **Verdict/decision emphasis uses accent colour, not bold.** Bold uppercase runs (`ESCALATE · DENY`, `PASS 0 · BLOCK 1`) would not fit a 260-unit column at 26 units under the width model, and shrinking text is prohibited, so emphasis is colour only.
4. **Mobile label line combines command and module.** The desktop command bracket has no vertical equivalent that keeps a 360 px column readable, so the mobile variant writes `actseal verify · assessment` etc. in the module slot; `actseal replay` absorbs the module name `replay`. A test pins the phrase-set difference exactly.
5. **Four outputs instead of one.** The provisional inventory declared a single `how-it-works.svg`; the dispatch asks for light/dark/mobile outputs, so the asset now declares `how-it-works-{light,dark}.svg` and `how-it-works-mobile-{light,dark}.svg`. Task 08's README `<picture>` markup should reference these names.
6. **Mobile canvas is 720×1904.** The height follows from one phrase per line at 30 units (two lines for the verdict run, one for the decision run); at 360 CSS px it displays about 952 px tall. I preferred full-size text to a shorter canvas.
7. **Bootstrap CLI tests changed meaning.** `test_check_on_bootstrap_repository_reports_planned_assets` assumed every asset was planned; it is now `…_reports_planned_and_uncommitted_assets` and asserts the exact error/planned mix, with a sibling write-then-check test. This is the minimal consequence of attaching the first renderer, not a relaxation.
8. Implementation was done directly by Fable 5.1 rather than delegated, following the dispatch's no-subagent instruction over the general routing preference.
