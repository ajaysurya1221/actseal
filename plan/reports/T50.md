  `EvidenceBundle` and publishes with `write_bundle`; the provider is closed

Deviations from spec (with reason)

- `--offline` with `--provider fixture` is a usage error (exit 3). The
  command shape allows the flag syntactically for both providers; silently
  ignoring a flag that has no fixture meaning would contradict the explicit
  failure principle. Reviewers may prefer acceptance; the change is one line.
- `lock` pre-parses both splits with the accepted `parse_cases` before
  building a provider, so malformed inputs never start a 120 s native worker.
  Cross-split leakage is still detected only inside `create_lock` (its check
  is private to locking), after the provider has been built and closed.
- Argparse messages echo the offending command-line token (for example the
  invalid provider choice or the unrecognized `--timeout-seconds`). These are
  the caller's own argv tokens, not file contents or OS-supplied paths; OS
  errors are reduced to errno text with no filename.
- The demo copies the eight inputs into `<out>/inputs` so the directory is
  self-contained and the user can rerun `verify`/`replay` by hand; the
  sealed bundles do not depend on these copies. Output subdirectories are
  `inputs/`, `bad/lock.json`, `bad/evidence/`, `fixed/lock.json`,
  `fixed/evidence/`.
- `demo` JSON reports a measured `duration_s`; it is output only, never
  written into any sealed file, so repeated runs stay byte-identical on disk.
- `__init__.py` under `demo_data` is a regular package marker (its bytes are
  part of the implementation fingerprint like every other source file); the
  data files themselves are not fingerprinted, which is why the demo seals
  their raw bytes into each lock instead.
- `runner.py` exposes `open_model`, `write_lock`, `collect`, `lock_run`,
  `verify_run`, `demo_run`, `DemoRun`/`DemoResult` and the `model_factory`
  seam. These are the composition the CLI needs and the only injection point
  tests use; no deadline, retry or alternative-schedule API exists.
