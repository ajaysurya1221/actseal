Changes (files + summary)

Finding 1 (P1, bounded read):
- `src/actseal/contract.py` `read_input_text(path, *, limit=MAX_JSON_BYTES)`:
  validates `limit` as a plain `int` (bool rejected) in `[1, MAX_JSON_BYTES]`,
  raising `SchemaError("limit: must be an integer in [1, 134217728]")`;
  opens the file in binary mode and calls `stream.read(limit + 1)` once, so at
  most `limit + 1` bytes are ever requested or buffered; then rejects
  `len(data) > limit`, then strict UTF-8 decode. OS errors still propagate.
- `tests/unit/test_contract.py`: a fixture monkeypatches `Path.open` so every
  `"rb"` stream is wrapped by a recorder of requested read sizes. Regression:
  1000-byte file with `limit=8` raises the size error, every recorded request is
  a positive int ≤ 9 and their sum ≤ 9 (no `read()`/`read(-1)`); `limit=1000`
  requests ≤ 1001; a 2-byte file with `limit=2` records exactly `[3]`. Ten
  invalid limits (0, -1, True, False, 1.0, 8.5, "8", None, MAX+1, 10**30) are
  rejected with the `limit:` message; MAX_JSON_BYTES and the default are
  accepted.

Finding 2 (P1, lock wire ceiling consistency):
- `src/actseal/locking.py`: new `_check_wire_size(lock)` requires
  `len(canonical_json(to_data(lock))) + 1 <= MAX_LOCK_BYTES` (the `+ 1` is the
  one terminal LF wire files add) and raises
  `SchemaError("lock: canonical document exceeds 33554432 bytes")`.
  `create_lock` applies it to the sealed lock before returning; `validate_lock`
  applies it first, before the seal, fingerprint, fault-inventory and inventory
  checks. `parse_lock` keeps its all-supplied-bytes limit and now rejects by
  character count before any UTF-8 copy (`len(text) > MAX_LOCK_BYTES`), encoding
  only non-ASCII text for the exact byte check. `_raw_sha256` rejects
  `len(text) > MAX_JSON_BYTES` before encoding and the encoded byte length after,
  so neither `create_lock` nor `validate_inputs` hashes an oversized document.
- `tests/unit/test_locking.py`: `wire_size` computed independently with
  `json.dumps(sort_keys, compact, ensure_ascii=False)` + 1. The test builds 31
  verification rows of exactly `MAX_ROW_BYTES` bytes (asserted) plus one
  adjustable row, measures the slack to the ceiling with a probe lock, then for
  ASCII and for two-byte filler: the exact-ceiling lock creates, `wire_size ==
  MAX_LOCK_BYTES`, validates, and `parse_lock` of canonical + LF (asserted to be
  exactly 32 MiB) round-trips; one more byte makes `create_lock` raise; a lock
  built around `create_lock` one byte over (resealed, inventory consistent) is
  rejected by `validate_lock` and `validate_inputs` with the canonical-size
  message and by `parse_lock` with its document-size message. The multibyte
  variant asserts fewer characters than bytes. Separate test: 128 MiB + 1 chars
  of spaces into `create_lock` and 64 Mi + 1 two-byte chars into
  `validate_inputs` are rejected with the `<field>_jsonl: document exceeds`
  message (cheap pre-encoding path).
