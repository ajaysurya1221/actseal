## Findings and repairs

1. **P1 — attestation kind and material.** The decoded statement must carry
   `predicateType == https://docs.pypi.org/attestations/publish/v1` and an
   empty predicate (`null`, `{}` or absent), in addition to the in-toto v1
   type and matching subjects. Each attestation must have `version` equal to
   the real integer 1, an `envelope.signature` that is non-empty valid
   base64, and `verification_material` with a non-empty valid-base64
   `certificate` and a non-empty `transparency_entries` list of objects.
   Unrelated predicate types, non-empty predicates, `!!!` signatures, empty
   material, garbage certificates, empty transparency lists and boolean
   versions all fail. The receipt note still says presence, identity and
   subjects were inspected; no cryptographic verification is claimed. The
   primary docs were not fetched in this offline session; the shapes follow
   PEP 740 and the PyPI publish/integrity documentation as previously read.
2. **P2 — strict recorded metadata.** `validate_metadata_record` is shared by
   live PyPI inspection and receipt revalidation: exactly the five keys,
   `yanked is False`, classifiers a list of non-empty strings with
   Production/Stable for 1.x, non-blank summary. `release-receipt`,
   `mirror` and `receipts` validate with `official_index=True`, requiring
   `index == https://pypi.org` and every recorded file URL under
   `https://files.pythonhosted.org/`. Only the isolated `postpublish` chain
   test keeps a `file://` index (`official_index=False`), and that test also
   asserts the same receipt is rejected at promotion. Schema versions,
   attestation versions and attestation counts use `_exact_int`/`type is
   int`, so `True` is rejected where `1` is required.
3. **P2 — workflow URLs.** `validate_release_receipt` requires `build_url`
   and `verification_url` to equal
   `https://github.com/ajaysurya1221/actseal/actions/runs/<id>/attempts/<attempt>`
   for the respective recorded attempts; foreign, mismatched or missing URLs
   fail `mirror` before any `gh` call and fail `receipts`.
4. **P2 — whole-string identity.** `fullmatch` is used for HEX64, 40-hex
   commit, version, SHA256SUMS lines and the bare artifact digest. Newline,
   leading-space and trailing-space regressions are tested alongside the
   valid bare-hex action output; nothing is trimmed.
5. **P2 — documentation anchors.** `same_repository_path` parses same-repo
   absolute URLs with `urllib.parse`, ignores fragments and query strings,
   percent-decodes the path and refuses `..` segments; relative document
   links are resolved the same way. Anchored and encoded links to existing
   files pass; missing files behind anchors, relative README links and
   bare `#top` still fail. Markdown and quoted/multi-line HTML anchor cases
   are covered.
