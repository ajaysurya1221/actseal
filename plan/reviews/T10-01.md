## Findings ordered by severity

1. **P1: read_input_text allocates an unbounded file before its size check.**
   contract.py:74 calls Path.read_bytes(). An instrumented binary stream with
   limit=8 records read(-1). A small configured ceiling therefore does not bound
   the read. Validate limit and read no more than limit+1 bytes before rejection.
2. **P1: create_lock returns locks that its own reader rejects.** locking.py:196
   seals without checking wire size. Root created 34 distinct verification cases
   with 1,000,000-character states, each legal under the row ceiling: canonical
   lock size was 34,007,125 bytes, above 33,554,432. Creation succeeded and
   parse_lock rejected it. Enforce canonical wire size including terminal LF at
   creation and validation; keep parsing consistent. Use cheap character-count
   checks before oversized text encoding in raw hashing/parsing paths.
3. **P2: validate_lock accepts cross-split ID overlap after a correct reseal.**
   A valid small lock with a calibration CaseRef ID replaced by a verification
   ID and a recomputed seal passed validate_lock. Both inventories are available.
   Reject intersecting IDs here, without claiming calibration-state recovery.
