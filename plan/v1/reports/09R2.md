## Findings and repairs

1. **Artifact digest (P1).** `normalize_artifact_digest` now accepts only the
   pinned upload-artifact's bare 64-hex `artifact-digest` output and stores
   `sha256:<hex>` in the receipt. `sha256:`-prefixed, truncated, empty or
   upper-case inputs are rejected. Tests use the bare form.
2. **Attestations (P1).** `_provenance` requires a non-empty bundle list where
   every bundle's publisher equals the expected trusted publisher
   (GitHub, `ajaysurya1221/actseal`, `publish-pypi.yml`, `pypi`), every
   attestation is version 1 with a non-empty signature and verification
   material, and the base64 in-toto statement decodes to JSON of type
   `https://in-toto.io/Statement/v1` whose subjects name the downloaded file
   with its actual sha256. Malformed base64/JSON, wrong statement type, empty
   subjects, wrong digest, wrong name, foreign publishers and missing fields
   fail. The receipt records `subject_sha256` and a note saying presence,
   identity and subjects were inspected, not cryptographically verified.
3. **Receipt evidence (P1).** `validate_build_receipt`,
   `validate_postpublish_receipt` and `validate_release_receipt` enforce typed
   fields and cross-links: 40-hex source commit, 64-hex lock hash, exact
   filename/size/sha256 inventory across build receipt, post-publication
   receipt and actual distributions, numeric run id/attempts, build run id
   equal to the current run and build attempt not later than the verification
   attempt, smoke checks exactly 0/0/1 with BLOCK/PASS statuses and the
   `installed_outside_checkout` flag, published metadata, inspected
   attestations and the verbatim note. The release receipt keeps the
   originating build attempt and the verification attempt separately with
   both URLs. `mirror` validates the whole receipt against the supplied bytes
   and checksums before any `gh` call. `receipts` reuses the same validators.
4. **No rebuild in the release matrix (P1).** `ACTSEAL_TEST_DIST` is the
   downloaded artifact directory, paired with `ACTSEAL_TEST_WHEEL`. Both
   packaging fixtures fail when the directory is set without the wheel or the
   wheel lies outside it. `release_support.release_distributions` returns the
   supplied files and never calls `uv build` when both are set, fails when only
   one is set or the directory does not hold exactly one wheel and one sdist,
   and builds locally only when neither is set. The workflow sets both. The
   proof test intercepts `uv` on `PATH` before any fixture runs and executes
   every packaging path (`tests/packaging`, acceptance wheel receipts and the
   release distribution chain) with supplied artifacts: zero build attempts.
5. **Asset regeneration gate (P1).** New `assets` job: locked `assets` group,
   pinned font/tool fetch through the accepted `setup_tools.py`, then
   `check_release.py assets`, which requires `docs/assets/src/render.py`, the
   Task 10 output names (`hero-light.svg`, `hero-dark.svg`, `how-it-works.svg`,
   `architecture.svg`, `social.png` at 1280×640), and a passing
   `render.py --check --only hero --only how-it-works --only architecture
   --only social`; a planned/not-implemented report fails. `demo` is excluded
   as the approved post-PyPI exception. `publish` and `mirror` need `assets`;
   the workflow check enforces the job, its steps and the dependency. The
   asset gate also runs inside `candidate`. Path constants were reconciled to
   `social.png`. No fonts or binaries were downloaded locally.
6. **Fixture-based gate tests (P2).** Real-repository "must fail" assertions
   were replaced with a deliberately incomplete 0.1.0/Alpha fixture tree. The
   only real-checkout test accepts exit 0 or a well-formed exit 1 report.
7. **Published metadata and HTML links (P2).** `postpublish` validates
   `info.name`, `info.version`, non-yanked release and files, packagetype per
   file, declared digests, Production/Stable for 1.x, and equality between
   PyPI's name/version/summary/classifiers and the downloaded wheel METADATA.
   `link_targets` parses Markdown targets plus HTML `href`, `src` and `srcset`
   (multi-line tags, single/double quotes, `>` inside alt text); README
   relative forms fail and same-repo absolute paths must resolve.
