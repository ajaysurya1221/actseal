## Acceptance criteria (testable)

1. Exact TOML/JSONL schemas reject unknown fields, wrong types, bool-as-number, nonfinite values, unsupported versions, duplicate/foreign labels, empty or oversized datasets and blank interior records. Preserve original UTF-8 state text and line-ending bytes for raw hashes. Apply the amended CONTRACTS limits: generic JSON 128 MiB, individual JSONL rows 1 MiB, lock 32 MiB, depth 32 and at most 10,000 cases per split.
2. Reject duplicate IDs and exact duplicate state texts within/across splits. Different literal text is not falsely advertised as independent or semantically deduplicated. Threshold is caller-prespecified; no selection against verification labels occurs.
3. Identical bytes/identity/implementation produce identical locks. Mutated raw data, labels, order, inventory, full cases, source fingerprint or self-seal cannot validate. Incoming locks are never silently resealed.
4. Exhaustive policy tests cover failure/fallback/disallowed/threshold branches, including exact threshold equality, known but not allowed labels, unknown choice and fallback on both answers/failures. Vendor confidence cannot change the result.
5. Package imports remain stdlib/model-free. Locking has no runtime dependency on the T30 fault module, avoiding the policy/fault cycle.
