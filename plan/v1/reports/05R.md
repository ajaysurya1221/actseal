## Changes

### 1. Credential echo in a successful body fails closed

`src/actseal/experimental/providers/jev.py`:

- `_HttpsExchange` keeps the key (`self._key`) alongside the header mapping it
  already held; nothing else holds it. After a 200 body is complete, within
  the byte cap and valid UTF-8, `_echoes_credential(text, key)` is checked
  **before** any `_Reply` carries text. A match returns
  `_Reply(None, "malformed_response", ("jev.credential_echo",))`: the capture
  has `failure_code="malformed_response"`, `body_json=None`, the fixed
  nonsecret warning, and the unsafe body is not retained, redacted, logged,
  formatted into any exception or visible in any `repr`. The response is
  treated as failure data, never modified and presented as original.
- Detection is exact-key: the literal key, or the key after resolving JSON
  string escapes (`\uXXXX` with either hex case, and `\" \\ \/ \b \f \n \r
  \t`) up to `_UNESCAPE_PASSES = 3` nested levels. Deeper nesting, base64 or
  any other encoding is explicitly **not** claimed to be detectable; the
  module docstring and a test state that limit.
- Every body that does not contain the key is captured exactly as before,
  byte for byte, including invalid JSON (the existing eight verbatim cases
  still pass unchanged).

### 2. Complete bounded HTTP framing before success

`src/actseal/experimental/providers/jev.py`:

- `_read_complete_body(response)` replaces the single
  `read(MAX_RESPONSE_BYTES + 1)`. It reads `_READ_CHUNK = 65536`-byte pieces
  until end of stream, stopping as soon as more than `MAX_RESPONSE_BYTES`
  actual bytes have arrived (then `jev.body_oversized`, framing not
  consulted). At end of stream it requires `response.length` (the declared
  fixed-length bytes still unread, exactly as `http.client.HTTPResponse`
  maintains it) to be `None` or `0`; otherwise `_IncompleteBodyError` ->
  `unavailable` with `jev.transport:incomplete_body`. A chunked body without
  its terminator or cut inside a chunk makes `http.client` raise
  `IncompleteRead` -> `unavailable` (`jev.transport:IncompleteRead`). A
  close-delimited body (no `Content-Length`, not chunked) is complete at end
  of stream. The cap counts received bytes regardless of `Content-Length`.
- The `_Response` seam protocol gained the read-only `length` property. Close
  on every path, one attempt, no retry and the timeout mapping are unchanged;
  the reviewer's reproduction (declared 192, delivered 182, complete choice
  JSON) is now `unavailable`, ESCALATE on evaluation, with `response.length ==
  10` observable in the test.

### 3. Offline setup is rejected before any environment read or transport

`src/actseal/experimental/providers/jev.py`:

- `JevModel(offline=True)` raises
  `ProviderSetupError("offline: the experimental Jev adapter has no offline
  mode; no request was made")` as the first statement of `__init__`, before
  `_api_key_from_environment()` and before `_HttpsExchange`/`_default_connect`
  exist. This is the approved PLAN E (line 352) reading; REPORT 05's "offline
  returns `unavailable` captures" interpretation is withdrawn. The constructor
  signature `(self, *, offline: bool = False) -> None` and default are
  unchanged (asserted by test). Importing the module remains key-free and
  performs no network, process or environment access.
- Removed the unused offline state: `_unavailable`, the `offline` parameter of
  the `_with_exchange` test seam and the `_Exchange | None` configure path.
  `close` behaviour is preserved (idempotent; later `decide` ->
  `unavailable` with `jev.unavailable:closed`; `_closed` flag kept for the
  conformance profile's open/closed stand-in). Laya's distinct cached-offline
  behaviour is untouched.

## Deviations

1. **Repair scope only.** No change to records, normalization, faults,
   runner, schemas, docs, `.env.example` (its Read remains denied and pending
   human approval; not attempted by any route) or REPORT 05.
2. **Detection limit stated, not a blanket claim.** The credential check
   covers the exact current key, literally or behind up to three nested
   levels of JSON string escapes. Base64, compression, encryption, partial or
   transformed keys and deeper nesting are not detected; the test asserts the
   base64 and four-level cases are not detected so the limit is explicit.
3. **Incomplete fixed-length transfer is `unavailable`, not
   `malformed_response`.** The reviewer specified "premature fixed-length/
   chunked EOF becomes unavailable"; both now map to `unavailable`
   (`jev.transport:incomplete_body` for fixed-length, the stdlib
   `IncompleteRead` class name for chunked). Over-cap data is still
   `malformed_response` (`jev.body_oversized`) before framing is consulted.
4. **Close-delimited completeness equals end of stream.** HTTP cannot
   distinguish a premature close from a normal one without a length or
   chunking; such a body is accepted as complete and then classified by the
   pure normalizer. Stated in the module docstring.
5. **`_closed` retained** although `_unavailable` was removed: the shared
   conformance profile reports it as the open/closed transport stand-in for
   the close-lifecycle checks (REPORT 05 deviation on `worker_alive`).
