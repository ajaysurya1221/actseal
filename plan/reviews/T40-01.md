## Findings ordered by severity

1. **P2 — embedded NUL can redirect publication to a different path.**
   evidence.py:240–241 filesystem-encodes paths and passes them to C string
   arguments without rejecting NUL. Path accepts such a string, and lexists
   reports it absent. A temporary independent probe of the actual macOS helper
   with requested `new\0suffix` returned successfully while publishing the
   marker under `new`. The requested path was never created. Reject embedded
   NUL before native calls/publication; validate both encoded source/destination
   and give the public writer a clear bounded error without filesystem effects.

2. **P2 — aggregate writer limit is enforced after potentially multi-gigabyte
   allocation.** evidence.py:140–147 collects every serialized row and joins
   them; lines168–184 check the128MiB aggregate only after all files exist as
   byte strings. Up to10,000 legal near1MiB rows can materialize about10GiB.
   Captures can share one padded raw-body string, so the caller's in-memory
   bundle need not already consume that space. Enforce the remaining aggregate
   budget incrementally across files/rows and stop at the first overflow,
   counting the manifest and every LF. Avoid serializing subsequent rows/files
   or making a huge final join once the ceiling is already exceeded. Preserve
   the exact row/lock/dataset wire rules and semantic checks.

3. **P2 — directory inventory buffering is unbounded.** evidence.py:320–321
   accumulates every scandir entry into a dictionary before checking the exact
   seven-name inventory. A malformed directory can contain arbitrarily many
   entries even though any eighth/unexpected entry is already invalid. Reject
   unexpected/duplicate/excess entries while iterating, without exhausting the
   iterator or retaining an unbounded inventory; preserve missing-entry checks
   and inspect no content until structural/size validation passes.
