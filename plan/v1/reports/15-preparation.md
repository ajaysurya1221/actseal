## Deviations and review-sensitive choices

1. **Private hero helper and lazy `tools` import, no toolchain edit.** `hero.py` exposes no public composition entry point; `social.compose` calls `hero._variant` rather than duplicating the layout code. A one-line public alias (for example `hero.variant = _variant`) would make this a stated contract; that edit belongs to the hero owner or integration. Likewise `tools.py` from-imports `inventory` names eagerly, so any renderer module registered in `inventory.py` must import `tools` lazily; changing `tools.py` to `from . import inventory` would remove the constraint but is a generic toolchain change outside this lane. Both are contract notes for Codex, not blockers.
2. **Assumed 640 CSS px display width.** Readability floors are enforced against an assumed half-scale link unfurl. The frozen contract says only "readable text" at 1280×640; the rendered review must confirm the sizes (36-unit caption and labels, 48-unit tagline, 120-unit wordmark) on the real card. The constant is `social.DISPLAY_WIDTH`.
3. **Three shared tests are stale by consequence and were not edited.** With the social renderer registered and neither the font nor resvg fetched, a bootstrap `--check`/`--write` now reports three `social` errors (`requires resvg 0.48.1: resvg 0.48.1 is not cached at <cache>/resvg-0.48.1/resvg; run setup_tools.py`, `requires jetbrains-mono 2.304; not fetched: …`, `skipped rendering because prerequisites failed`) and the summary becomes `0 asset(s) checked; 6 planned/not implemented; 5 error(s)`. `tests/visual/test_render_cli.py` still lists `social` in `PLANNED` and expects `7 planned … 2 error(s)`, so `test_bootstrap_repository_reports_planned_assets_and_missing_hero_font[--check|--write]` and `test_render_script_runs_without_fonttools` fail. That is the fail-loud behaviour this task requires; the tests are not owned by this lane and were neither edited nor suppressed. Suggested reconciliation at integration: move `social` into an `IMPLEMENTED_NEEDING_TOOLS` tuple, assert its three errors by prefix (the resvg message carries a cache path and differs on platforms without a pinned artifact), and update the counts; Task 12's reshaping of the same file must be kept too.
4. **Light palette, stacked layout, one PNG.** The social card uses the hero's light palette and the stacked (mobile-like) arrangement at card proportions, with the motif widened to span the text column. No dark variant is produced; the contract asks for one upload-ready PNG. The side-by-side desktop arrangement was considered and rejected for the 2:1 card because it forces the tagline below 20 px at half scale.
5. **Real-font fit is verified only at render time.** Line breaks were planned against the nominal 0.6 em advance (JetBrains Mono's advance is 600/1000); the outline double uses the same figure, so the fit checks are representative but not proof. Planned slack: caption line 2 at 883 of 1152 units, tagline line 1 at 749 of 1152, wordmark 504 of 1152, labels at most 130 of 288 inside a pill. If the real advance differs, `render()` raises and the fix is a line break or canvas constant, never a smaller size.
6. **Pin verification of fonts stays in the pipeline.** As for the hero, `social.render` checks font presence only; hash verification is the pipeline's blocking `fonts` scope. resvg, by contrast, is hash-verified inside `render` through `tools.verified_binary` on every call, because nothing else in the pipeline would otherwise bind the executed bytes to the pin at execution time.
7. Implementation was done directly by Fable 5.1 rather than delegated, following the dispatch's no-nested-executor instruction over the general routing preference.
