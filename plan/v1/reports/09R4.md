## Changes (Claude-authored, V1-012 paths plus the owned versioning paragraph)

- `docs/release-schemas/build-receipt.schema.json`,
  `postpublish-receipt.schema.json`, `release-receipt.schema.json`: Draft
  2020-12 promotion-profile schemas with the exact field sets from REVIEW 09R4
  at every object level (`additionalProperties: false`, every property
  required). Identity patterns anchor the absolute end of the string
  (`$(?![\s\S])`) so trailing newlines fail under Python's `re`. The release
  schema reuses the build and post-publication definitions by URN `$ref`
  (`Version`, `Tag`, `GitSha`, `Sha256`, `Decimal`, `Distributions`,
  `EmbeddedPostpublish`). The 1.x Production/Stable requirement is an
  `if`/`then` on the version. Inspection-only receipts (rehearsal builds with
  null tag/commit/run, `file://` or test indexes, tolerated missing
  attestations) fail the schemas. Descriptions state that provenance fields
  record inspection, not cryptographic verification, and that `lock_sha256` is
  the `uv.lock` hash.
- `docs/schemas/README.md`: a "Release receipts" index section linking the
  three schemas, explaining the sibling directory, the `uv.lock` meaning, the
  inspection-only cases, where the helper is stricter than JSON Schema, and the
  test module. The existing product-schema table is unchanged.
- `docs/decisions/0016-release-promotion-and-receipts.md`: concise ADR for
  build-once/promote-same-bytes, the gates before upload, post-publication
  verification and draft mirroring, strict receipts, and the attestation
  inspection boundary.
- `docs/versioning.md`: the single release-receipt section rewritten for the
  three receipts and corrected so `lock_sha256` is explicitly the SHA-256 of
  the repository `uv.lock` at the source commit, not an Actseal decision lock.
  No other section touched.
- `tests/release/test_release_schemas.py` (96 tests): validates receipts the
  helper actually writes (a tagged `build_receipt`, the `release_receipt`
  output re-read from disk and, under the `packaging` marker, the real-wheel
  `postpublish` receipt) with the dev-only validator over a local
  non-fetching registry; rejects unknown and missing fields at every object
  level of all three schemas; one negative per strictness boundary (schema
  version `2`/`"1"`/`True`, zero/zero-padded/non-ASCII/integer IDs, newline
  suffixes, uppercase or short hashes, bare digest, foreign run URLs, size
  `0`/`1.5`/`"1"`, one or three or duplicate distributions, `file://`/test
  index, foreign file host, yanked or string or empty or Alpha classifiers for
  1.x, altered notes, `present: false`, zero/boolean/float attestation counts,
  foreign publisher identities, every wrong smoke outcome); records that
  `const: 1` admits `1.0` in JSON Schema while the helper rejects it; shows the
  cross-field rules (tag/version, URL-attempt agreement, attempt ordering,
  subject digest, publisher-count floor) stay with the helper; and proves the
  rehearsal build and the unattested post-publication run never match.
