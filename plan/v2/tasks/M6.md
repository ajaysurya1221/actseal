## Interface contract

### `actseal report`

- `actseal report DIRECTORY --out OUTDIR` where DIRECTORY is a qualification
  output (calibration directory, evidence bundle and `qualification.json`) or a
  plain v1 evidence bundle.
- It first validates and replays offline (bundle replay, and selection replay
  when a calibration directory is present). A report is never rendered from
  evidence that does not replay; that case exits 3.
- Writes exactly: `report.html` (one self-contained file: no script, no
  external request, inline CSS and inline SVG only), `report.md` (suitable for
  a GitHub job summary) and `badge.json` (shields.io endpoint schema:
  `schemaVersion`, `label`, `message`, `color`).
- Content, in this order: verdict; the risk limit and confidence; accepted
  count, error count, the risk interval and the coverage interval from the
  verdict; the selected threshold and how it was selected (grid, target,
  calibration counts) when present; a calibration risk-coverage chart labelled
  "descriptive, not verified"; model identity; provider scope notes (for
  example `recorded: provider faults not tested`); SHA-256 of the lock,
  manifest and calibration manifest; the exact replay commands.
- Fixed sentence under every verdict: what the result does and does not show
  (take the wording from `docs/statistical-contract.md`; fixed benchmark, one
  prespecified attempt, not proof of label truth or of deployment behaviour).
- The words "guaranteed", "certified", "safe" and "best" never appear.
- Attestation: the report prints "attested" only when `--attestation-ref TEXT`
  is supplied by the caller; otherwise it prints "checksummed, not attested".
  Actseal itself verifies no signature and says so.
- Output is byte-deterministic for the same input: no timestamps, no absolute
  paths, stable ordering, fixed float formatting.
- Rendering lives in new `src/actseal/report.py` (stdlib only). It is excluded
  from the implementation fingerprint by name, so it must contain no decision
  logic: it reads the verdict and selection result and never recomputes them.
- All user-supplied strings are HTML-escaped. Add a test with hostile labels
  and model names.

### GitHub Action (`action.yml` at the repository root, composite)

- Inputs: `mode` (`qualify`, `verify` or `replay`), `args` (passed to that
  command), `version` (Actseal version to install, default the current
  release), `python-version` (default 3.13), `report` (default true),
  `upload-evidence` (default true).
- Steps: set up Python, install the pinned `actseal` from PyPI, run the
  command, render the report, append `report.md` to `$GITHUB_STEP_SUMMARY`,
  upload the output directory as an artifact, and exit with Actseal's exit
  code (0 PASS, 1 BLOCK, 2 INCONCLUSIVE, 3 ERROR). Outputs: `verdict`,
  `exit-code`, `evidence-path`.
- No attestation step inside the action. Document, in `docs/github-action.md`,
  the optional follow-up step with `actions/attest` and
  `gh attestation verify`, and state plainly what such an attestation covers
  (that this workflow run produced these bytes) and what it does not.
- Third-party actions are pinned to full commit SHAs, following `ci.yml`.
  Inputs reach the shell only through environment variables, never by direct
  interpolation into a script (script-injection rule).
- Add a self-test workflow `.github/workflows/action-selftest.yml` that runs
  the action from the checkout in `replay` mode on a committed bundle and in
  `qualify` mode on the packaged demo. If the action must install from the
  checkout rather than PyPI for the self-test, add an explicit `source` input
  for that; do not special-case silently.

## Tests

- Byte-determinism: two renders of the same input are identical.
- Refusal: a tampered bundle or calibration directory produces no report and
  exit 3.
- HTML: parses with `html.parser`; contains no `<script`, no `http://` or
  `https://` resource reference other than plain text replay instructions;
  hostile strings are escaped.
- Banned-word test over the templates and `docs/github-action.md`.
- `badge.json` validates against the shields endpoint shape.
- `action.yml`: a test parses it (stdlib only; if no YAML parser is available
  without a new dependency, check the pinned-SHA and env-only-input rules with
  a strict line-based test and say so).
