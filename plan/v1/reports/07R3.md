REPORT 07R2 said the committed archive would fail "until Task 19's explicit
compatibility review either records a fresh identified run or approves both
fingerprints in the registry". The first alternative was wrong under
V1-020: recording a fresh run cannot make the older active archive
`recorded/a5fe090202f7` pass, because every active archive must itself
replay non-`ERROR` and equal its archived verdict. The correct statement is:
after any product source change, that archive passes only if Task 19's
explicit compatibility review approves both its producer fingerprint
(`a5fe090202f75b07510407937a86ae35a7653a75eab3f4daa2d0ace2e7641642`) and the
final running fingerprint in the packaged registry; removing it from the
active set would require a separately recorded amendment, and none exists.
A new `--record` run is a separately identified run beside it, never a
repair, replacement or reseal. REPORT 07R2 itself is left as written
(history); this report is the appended correction.
