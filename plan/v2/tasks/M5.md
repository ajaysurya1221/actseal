### Selection plan (fixed)

A strict document written and hashed **before** any calibration response is
collected. It holds: the contract fields except the threshold; the threshold
grid (1..32 strictly increasing values in (0, 1], supplied by the user or the
documented default grid, never derived from scores); `target_pass_probability`;
`selection_tail`; the verification size the lock will schedule; the SHA-256 of
the calibration cases and of the verification cases; the model identity; the
implementation fingerprint. Calibration and verification case ids must be
disjoint; overlap is an error.

### Calibration directory (fixed set of files, strict manifest with SHA-256s)

`selection_plan.json`, `calibration.jsonl` (cases), `records.jsonl` (captured
outcomes, same record types the verification path stores), `selection.json`
(the `SelectionResult`: every grid point's accepted and error counts, the
predicted pass probability, the selected threshold or the reason), and
`manifest.json`. Written with the existing exclusive-publication and size
budget helpers in `evidence.py`. Reuse; do not duplicate.

Mapping a calibration case to `CalibrationCase`: `score` is the gating value
when the policy could ACT on that case at some threshold (answer present,
choice allowlisted, no fallback), otherwise `None`; `correct` is choice ==
expected label. Use the existing policy code to decide eligibility; do not
re-implement precedence.

### Commands (names fixed; existing commands, options, receipts and exit codes unchanged)

- `actseal plan --max-risk R --min-coverage C --alpha A --expected-risk r
  --expected-coverage c [--target-pass-probability P]` → required verification
  size or "not reachable within 10,000"; no files, no model.
- `actseal calibrate` → writes the calibration directory and a derived
  contract file carrying the selected threshold. No threshold qualifies → exit
  2, reason `calibration.no_threshold`, no derived contract.
- `actseal qualify` → selection plan, calibrate, then the existing lock and
  verify on the verification cases, then a `qualification.json` receipt that
  links the calibration manifest SHA-256, the lock SHA-256 and the verdict.
  Exit code is the verdict's. If no threshold qualifies, verification
  responses are never collected.
- `actseal replay-selection DIRECTORY` → offline: validates the manifest,
  re-derives every grid point's counts from `records.jsonl`, recomputes the
  selection with `selection.select_threshold`, and requires the same selected
  threshold and the same counts. Any tampering → exit 3. Predicted
  probabilities are compared with a small documented tolerance (they come from
  `math.lgamma`, which may differ in the last bits across platforms); a
  different selected threshold is always an error. Imports no adapter.
- All new JSON receipts carry `schema_version: 1` and get published JSON
  Schemas under `docs/schemas/`.
- Works with every provider: `fixture`, `recorded`, `laya`, `jev`,
  `decision-api`.

## Tests

- End to end on fixtures: `qualify` → PASS; a no-threshold case → exit 2 and no
  verification records; `replay-selection` reproduces the selection.
- Tamper tests: change one calibration record, one grid value, the plan's
  verification size, or the manifest → exit 3.
- Overlapping calibration and verification ids → error.
- Order independence: shuffled calibration rows give the same selection.
- Isolation: `replay-selection` imports no adapter (extend the existing
  `sys.modules` test).
- Docs tests: quickstart commands execute; the words "guaranteed",
  "certified", "safe" do not appear as claims in new help text or docs.
