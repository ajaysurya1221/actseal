## Findings ordered by severity

1. **P1: blocking writes bypass the request deadline.** laya.py:473 writes and
   flushes synchronously; line652 starts the receive timeout afterward. Root's
   ready child stopped reading for0.8s; a1,000,000-character request with timeout
   0.05s returned unavailable after0.814s. Another reviewer independently reproduced
   this. Use one deadline covering send and receive, bounded partial writes, and
   bounded cleanup. A nonreading worker must produce timeout and be joined.
2. **P2: malformed IPC can escape with a live worker.** laya.py:514 uses json.loads
   without a depth bound or RecursionError handling. Root and another reviewer
   sent a20,001-byte nested JSON reply; RecursionError escaped, child_alive=True,
   invalidated=False. Use bounded strict protocol parsing; all unusable messages
   produce unavailable with termination/join and permanent invalidation.
3. **P2: Linux native tests reject the approved CPU build.** test_laya.py:45/72
   require torch2.14.1 everywhere. The frozen Linux graph is2.14.1+cpu. Apply the
   exact approved platform mapping to prerequisites and observed identity checks.

   reads the whole file before row checks. A read-only reviewer accepted129 legal
   rows totaling135,071,791bytes, with read(-1). ADR0011 explicitly supplies the
   previously ambiguous aggregate fixture ceiling:128MiB, enforced before decode,
   split and hash using a bounded read. Preserve raw-byte identity and row limits.
