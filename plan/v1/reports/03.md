## Changes

- `tests/provider_support.py` (new). Shared provider test support extracted
  from `tests/unit/test_providers.py`: `ROW_OK`, `ROW_FAIL`, `write_rows`, the
  `FAKE_WORKER` script, `pinned_identity`, `spawn`, `child_alive`, new
  `child_pid` and `write_fake_worker`. The fake worker gains two data-driven
  modes: `failure-from-env` (replies with the failure code and warnings from
  `ACTSEAL_FAKE_FAILURE` / `ACTSEAL_FAKE_WARNINGS`) and `raw-body-from-env`
  (splices the exact bytes of `ACTSEAL_FAKE_BODY` into the reply frame so the
  parent sees the provider's own non-canonical serialization). Existing modes
  are byte-identical. New `independent_request_digest` recomputes the request
  digest with `json` + `hashlib` over a hand-built mapping (no actseal
  serialization), so captured digests are compared against something other
  than `request_sha256`. Two provider profiles declare provider facts instead
  of skipping: `FixtureProfile` (no transport; close is a no-op and the model
  stays usable; recorded `timeout` rows leave it usable; body text verbatim)
  and `FakeLayaProfile` (one resident child; close releases it and later
  `decide` is `unavailable`; a real timeout terminates the worker, later calls
  are `unavailable` with the same pid; body text is canonical JSON of the full
  native object; setup warnings are prepended). Shared checks are plain
  functions over the public protocol: `check_protocol_shape`,
  `check_identity_immutable` (frozen record, same value every call),
  `check_request_binding` (nine variants differing in case id, state,
  trailing whitespace, Unicode state, question id, instructions, option order
  and option description; every captured digest equals the independent digest
  and all are distinct), `check_timeout_validation` (0, 0.0, -1.0, -0.0, ±inf,
  nan, True, False, 10**400 overflow, "30", None, list: each must raise
  `SchemaError` naming `timeout_s`; acceptance raises `AssertionError`),
  `check_typed_failure`, `check_body_preserved` (documented text form plus
  JSON-value equality, so no field may be removed or repaired),
  `check_valid_body_normalizes`, `check_identity_mismatch_precedes_body`
  (seven foreign identities differing in one field each; always
  `identity_mismatch`, even for malformed bodies and provider failures),
  `check_close_lifecycle` and `check_after_timeout`. `capture_or_fail` turns a
  raised exception from `decide` into an assertion failure.
  REVISE fix: `check_timeout_validation` no longer asserts inside the
  `except SchemaError` block (Ruff PT017); it records the message in the
  handler and asserts after it, so a lenient double is still rejected and the
  lint rule is untouched.
- `tests/conformance/test_provider_contract.py` (new, 45 collected cases).
  One `profile` fixture parametrized over `PROFILE_NAMES == ("fixture",
  "laya-fake")`; every case runs for both profiles with no skip, xfail or
  provider branch. Cases: profile coverage guard, protocol shape and identity
  stability (including deterministic repeat capture), request-hash binding,
  invalid timeouts before any transport (`requests_sent == 0`, worker still
  alive, healthy request afterwards), non-`DecisionRequest` rejected with
  `SchemaError`, all eight failure codes as typed captures with warnings
  preserved and identity mismatch taking precedence, timeout capture plus the
  profile's documented aftermath, seven semantically malformed JSON-object
  bodies captured as evidence then rejected by normalization as
  `malformed_response` (identity mismatch still precedes), valid raw body
  preserved without repair (optional `action`/`answer_confidence` fields
  survive; warnings order and duplicates preserved; normalizes to `billing`
  with `provider_confidence` 0.25), and close idempotence with identity
  outliving close.
- `tests/conformance/test_provider_doubles.py` (new, 17 collected cases).
  Negative evidence that the shared checks are not vacuous: an honest fixture
  passes every check; doubles that violate one rule each are rejected. Sixteen
  cases expect `AssertionError` (wrong request hash, foreign capture identity,
  drifting identity, raising `decide`, repaired body, canonicalized text under
  a verbatim profile, lenient timeout, fallback flag, wrong failure code,
  dropped warnings, identity change on close, post-close behaviour contrary to
  the declared profile in both directions, live worker after close,
  answering/live/restarted worker after timeout, positional `timeout_s` and
  missing `close`); the non-idempotent-close double is rejected by its own
  `RuntimeError` propagating out of the shared check, which is the documented
  expectation for that case.
- `tests/conformance/test_provider_isolation.py` (new, 1 case). A fresh
