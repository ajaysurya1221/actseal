Changes (files + summary)

- `src/actseal/adapters/laya.py` — Finding 1 (P1): the worker channel now uses
  one deadline covering send and receive. Both child pipes are nonblocking;
  `_Worker.exchange(message, timeout_s)` computes a single monotonic deadline,
  `send_until` writes with `select` + bounded partial `os.write` loops and
  raises `timeout` when the worker stops reading, then `receive_until` reads
  under the same deadline. `decide` uses `exchange`; a timeout during the write
  invalidates, terminates (grace), kills if needed, joins, and returns
  `timeout`. The graceful close message is also written under the close grace
  deadline. Finding 2 (P2): `_decode` parses replies with
  `actseal.serialization.strict_json_loads` (1 MiB line cap, depth ≤ 32,
  duplicate keys, nonfinite constants) and maps `SchemaError`, `RecursionError`,
  `UnicodeDecodeError` and `ValueError` to `ipc`; every unusable message yields
  `unavailable`, terminate/join and permanent invalidation (startup messages
  yield `ProviderSetupError` with no child left). The worker also parses parent
  lines strictly and exits on malformed input (parent then observes
  `worker_exit`). Startup read uses the same bounded reader.
- `src/actseal/adapters/fixture.py` — Finding 4 (P2, ADR 0011):
  `MAX_FIXTURE_BYTES = 128 MiB`; the file is read with `handle.read(limit + 1)`
  and rejected with `SchemaError("responses: file exceeds …")` before UTF-8
  decoding, splitting, row parsing or hashing. Row limit (1 MiB) and raw-byte
  identity are unchanged.
- `tests/integration/test_laya.py` — Finding 3 (P2): expected torch version is
  `2.14.1+cpu` when `sys.platform == "linux"` and `2.14.1` otherwise; the
  prerequisite check and the identity assertion use that mapping. Observed
  versions still enter identity unchanged; no new runtime guard was added.
- `tests/unit/test_providers.py` — regression tests: nonreading worker with a
  1,000,000-character request and 0.3 s timeout returns `timeout` in under 2 s
  with the child joined and later calls `unavailable:timeout`; a small request
  to a nonreading worker also times out; deep-nested (10,001-level) and
  duplicate-key replies are `unavailable:ipc` with the child dead and later
  calls still unavailable (parametrized with the existing garbage/huge cases);
  deep JSON at startup raises `ProviderSetupError` leaving no child; fixture
  file of 130 legal sub-1 MiB rows over 128 MiB is rejected; exact aggregate
  boundary (limit accepted, limit+1 rejected) and limit-before-row-parsing
  using a monkeypatched module limit. New fake-worker modes: `stop-reading`,
