Changes (files + summary)

- src/actseal/serialization.py (REVIEW T00-02 P2)
  - `_scan_depth` no longer uses regex string blanking. It is a two-state scan
    (outside/inside string literal) driven by one monotonically advancing cursor:
    outside strings `re.search` jumps to the next quote or bracket; inside
    strings it jumps to the next quote or backslash and skips the escaped
    character. Every character is visited at most once, so cost is linear for
    well-formed, malformed and truncated input alike. An unterminated string
    ends the scan and leaves the error to `json.loads`. Depth, duplicate-key,
    nonfinite and Unicode semantics are unchanged.
  - `_byte_length` replaced by `_exceeds_byte_limit(text, limit)`: a character
    count above the limit is rejected before any UTF-8 encoding is allocated
    (character count is a lower bound on byte count); ASCII text never encodes;
    non-ASCII text at or under the character limit is encoded with
    `surrogatepass` for an exact byte count.
- tests/unit/test_serialization.py
  - Correctness table for escaped quotes, escaped backslashes, brackets inside
    strings, `[`-style escapes and a backslash-then-brackets string.
  - Truncation table (`"`, `"\`, `"\"`, 1000 escaped quotes with no terminator,
    trailing backslash runs, unterminated nested forms) all raise SchemaError.
  - Depth enforcement after escaped strings (31 accepted, 32 rejected inside a
    wrapping array).
  - Coarse subprocess deadline regression: a child process must reject a
    64 KiB and a 2 MiB adversarial `"` + `\"`×N input within a 20 s
    `subprocess.run` timeout (no microbenchmark assertions).
  - `_exceeds_byte_limit` probe test using a `str` subclass that records
    `encode` calls: oversized character counts and ASCII text never encode;
    only non-ASCII text under the character limit does; surrogates count as 3
    bytes; a non-ASCII document over the limit is rejected by
    `strict_json_loads`.
