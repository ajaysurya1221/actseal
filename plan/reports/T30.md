Deviations from spec (with reason)

- `src/actseal/adapters/__init__.py` added (docstring only) so the adapters
  directory is a regular package; the spec lists only the three modules.
- `request_sha256` lives in `normalization.py` (not adapters) so T20/T40 can
  reproduce capture hashes without importing adapters; both adapters use it.
- `LayaModel._spawn(...)` private alternate constructor and `_child` attribute
  exist only as test seams; `LayaModel(*, offline=False)` is unchanged and
  always uses the 120 s startup bound, 5 s close grace and the native worker.
- Timeout validation raises `SchemaError` (field `timeout_s`); the contract
  does not name the exception type.
- Runtime identity includes `machine`/`system` (arm64/Darwin) but not the OS
  version or the offline flag: architecture affects float results, OS patch
  level and library offline flags do not.
- Fixture `close()` is a no-op; captures remain available after close (the
  contract specifies nothing for the fixture).
- Normalization warnings are bounded codes (`normalize.<check>`); unknown
  choice is detected before probability-key validation, as the contract orders.
- Laya load/predict warnings keep the upstream message text bounded to 256
  characters so the calibration warning is fully preserved.
- Fixture rows: one SchemaError family for all content problems (schema and
  duplicates); ProviderSetupError only for unreadable file and missing
  requested case.
