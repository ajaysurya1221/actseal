## Design choices

1. **Replay before rendering.** The CLI uses the existing bounded bundle
   reader and replay stages without duplicating assessment, normalization,
   policy or statistics. The public replay facade maps invalid evidence to an
   ERROR verdict, so its internal stages are reused to distinguish invalid
   evidence from a valid diagnostic ERROR. Qualification also replays selection
   and binds the receipt, raw manifest, top-level lock, selected threshold,
   non-threshold contract, model/producer/engine identities, both input hashes,
   verification size and raw calibration bytes. Invalid inputs publish nothing.
2. **Presentation only.** `report.py` accepts validated records and copies
   their verdict, counts, intervals and selection. Empirical calibration
   ratios are chart coordinates only, labelled `descriptive, not verified`.
   HTML uses inline CSS/SVG; Markdown uses a text chart and grid table. Fixed
   numeric formatting, stable order and portable relative replay commands
   make all three files byte-deterministic. HTML and Markdown escape caller
   strings. Publication is atomic, refuses existing destinations, and cannot
   write inside a strict evidence/calibration directory.
3. **Exit and provenance semantics.** Successful report publication exits 0,
   including when the displayed verdict is BLOCK, INCONCLUSIVE or a replayed
   diagnostic ERROR; invalid input exits 3. Calibration-only/no-threshold
   output has no verification verdict and is refused. The new report JSON
   receipt is documented in the CLI reference; existing published receipt
   schemas are unchanged. Reports default to `checksummed, not attested`;
   a supplied reference is explicitly a caller assertion. Actseal verifies
   no signature.
4. **Action boundaries.** The composite action installs into an isolated
   environment, passes inputs through environment variables, splits arguments
   with `shlex` and invokes argv without shell evaluation. It preserves the
   original command's 0/1/2/3 result through reporting and artifact staging.
   Only enumerated evidence filenames are copied, with no symlinks or unrelated
   files. Reporting failure is visible in the summary and warning. Existing
   approved setup-uv, checkout and upload-artifact SHAs are reused:
   **no `tools/check_release.py` allowlist change is needed**.
5. **Explicit development installation.** Default PyPI version stays the
   current release, 1.0.1; that release lacks `qualify` and `report`. The
   documented `source: checkout` input is used by both self-test jobs until
   the new release exists. The action adds no attestation step. Documentation
   gives a separate pinned `actions/attest` example and external
   `gh attestation verify`, limiting the claim to the workflow's output bytes.
