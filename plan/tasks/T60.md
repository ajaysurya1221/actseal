## Acceptance criteria (testable)

1. Real public workflow produces bad BLOCK, fixed PASS and insufficient-evidence INCONCLUSIVE; malformed usage/input is ERROR3. Recorded source/model/threshold/schema/label/implementation changes invalidate locked evidence instead of silently certifying a new experiment.
2. Exact inventory enforcement rejects omissions, duplicates, foreign/reordered cases, swapped request/question hashes and missing/duplicated/swapped canonical faults. Nonfatal captured failures remain denominator observations without receiving ACT. Regular Laya timeout/unavailable instead produces complete diagnostic ERROR evidence with infrastructure.worker_invalidated, zero counts and [0,1] intervals; all terminal records remain, and synthetic faults are excluded from that rule. Fallback flags cannot acquire ACT.
3. Rehashed changed normalized probabilities, stored decisions, scenario captures, gold references or verdict counts produce ERROR after real semantic replay. Boundary probability/threshold behavior and zero-accepted cases cannot false-PASS. Replaying or duplicating a run never creates more statistical observations.
4. Provider-free demo/replay run in a fresh subprocess with prohibited imports/network paths instrumented to fail. Bundles containing executable-looking strings remain inert. Symlink/traversal/extra-file and size/depth limits are enforced on pytest-owned temporary paths, with no effects outside them.
5. README quickstart commands correspond to the installed CLI and measured fixture path. Run full default/packaging suite after accepted fixes; inspect actual outcomes, not only test counts. Any unresolved false PASS or missing live/local requirement blocks release acceptance.
