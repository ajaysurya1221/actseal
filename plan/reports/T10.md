Deviations from spec (with reason)

- Extra public names beyond the frozen six signatures, none changing a frozen
  signature: `contract.read_input_text(path, *, limit=MAX_JSON_BYTES)` and
  `contract.MAX_ROW_BYTES`; `locking.FAULT_INVENTORY`, `locking.MAX_LOCK_BYTES`,
  `locking.parse_lock(text)`, `locking.lock_digest(lock)`,
  `locking.case_digest(case)`; `policy.REASON_*` constants. `parse_lock` exists
  because acceptance criterion 1 requires the 32 MiB lock limit to be applied by
  T10; `read_input_text` is the path-based exact-byte reader CONTRACTS §3
  describes and `parse_contract` needs it anyway; `lock_digest`/`case_digest`
  are the hash definitions T40/T50 must reuse rather than re-derive. If Codex
  prefers these private, renaming is a one-line change each.
- TOML diagnostics name the record path, so the `[risk]` table reports as
  `Contract.limits.<field>` and the top-level as `Contract.<field>`; the
  contract decode is a single strict `from_data(Contract, ...)` call rather than
  a parallel TOML-specific validator, so T00's rules apply byte-for-byte.
- `validate_lock` compares `implementation_sha256` with the *current*
  `implementation_fingerprint()` (criterion 3 "source fingerprint ... cannot
  validate"; PLAN "changing product code requires new evidence"). Consequence
  for downstream lanes: any lock or bundle must be validated under identical
  `actseal/**/*.py` bytes, and demo evidence must be regenerated after T20/T30/
  T40/T50 land. `parse_lock` deliberately does not validate; callers run
  `validate_lock`.
- Blank-row rule: exactly one terminating LF is accepted; a file without a final
  LF is accepted; any other empty/whitespace-only row (leading, interior or
  trailing) is rejected. CR-only separators fail as invalid JSON. BOM-prefixed
  JSONL fails on row 0 (JSON rejects the BOM) and a BOM-prefixed TOML fails as
  invalid TOML; neither is stripped.
- Dataset-shape problems found while locking or validating inputs (malformed
  rows, duplicate or leaked cases) raise `SchemaError`; lock/evidence mismatches
  (seal, fingerprint, fault inventory, raw hashes, inventories, embedded cases)
  raise `IntegrityError`. Parse errors inside `create_lock`/`validate_inputs`
  are prefixed with the split name (`calibration: cases[2]...`).
- Cross-split leakage is checked in both `create_lock` and `validate_inputs`
  (a lock sealed over leaking data by bypassing `create_lock` is rejected);
  `validate_lock` alone can only check verification-internal uniqueness because
  calibration cases are not embedded.
- The import-hygiene test uses one fixed-argument `subprocess.run` of
  `sys.executable -c` (noqa S603), the same pattern T00 used; it is not an agent
  and makes no network call.
